# Delivery verification

Make one completion decision over the actual final scope, conformance findings and
evidence collected during construction. Reuse completed checks that apply to the
delivered code and environment. A relevant edit invalidates dependent evidence;
it does not restart every check or demand a separate final repetition.

Completion requires no conformance blocker, resolved or explicitly accepted
warnings, and suitable evidence for changed behavior, laws, structure, cost and effects.
Use project-declared checks applicable to that scope, retaining any mandatory
project gates. Add a check for a consequential uncertainty it can resolve; expand
beyond the affected scope when a real dependency or project requirement needs it.
Inspect the actual artifacts and results. A started job, old CI, invented RED or
unobserved output does not establish a claim.
Regression tests and deployed operational acceptance support different claims.

For effects, use authorized disposable scope and observe surviving state and
cleanup. Inspect generated schemas, packages, logs or rendered output when they
are the claimed result. Keep ad hoc verification task-scoped and its relevant
inputs/results inspectable; no evidence ledger or wrapper framework is required.

Report actual scope, salient commands/outcomes, limitations and remaining risks,
including relevant documentation, automation or release impact. Keep failures,
skips and unavailable checks explicit, bound to the code/environment they concern.
Local completion grants no review, merge, publication or other external authority.
